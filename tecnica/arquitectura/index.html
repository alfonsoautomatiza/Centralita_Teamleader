    Arquitectura del Sistema

    Contexto de la Aplicación

    Descripción

    Sistema de gestión de llamadas con IA que integra telefonía, grabación de audio, transcripción automática con inteligencia artificial y sincronización con CRMs como Teamleader. Centraliza la gestión de llamadas entrantes/salientes, automatiza el resumen de conversaciones y mantiene un registro estructurado de todas las interacciones.

    Stack Tecnológico

    • OBS Studio: Grabación de audio del sistema (opcional)
    • OpenRouter API: Transcripción con IA (Google Gemini)
    • Teamleader API: Integración con CRM

    Público Objetivo

    PYMEs españolas que utilizan Teamleader como CRM y necesitan automatizar la gestión de llamadas telefónicas con transcripción IA, especialmente empresas de servicios, call centers y equipos de ventas.

    Arquitectura Frame-Driven

    El sistema usa una arquitectura de "frames" en FRAMES/ que permite diferentes implementaciones por integración CRM (Teamleader, Sage 50, etc.).

    Concepto de Frames

    Los archivos en la raíz (conf.py, cuadro.py, procesos.py) son shims que delegan al frame activo resuelto por: - Variable de entorno CENTRALITA_FRAME - Rama git activa - Configuración en config.ini

    Estructura de Frames

    FRAMES/
├── main/              # Frame principal (Teamleader)
│   ├── conf.py        # Configuración Teamleader
│   ├── cuadro.py      # Cuadro de mando
│   └── procesos.py    # Procesos específicos TL
├── sage50/            # Frame Sage 50 (si existe)
│   ├── conf.py
│   ├── cuadro.py
│   └── procesos.py
└── README.md          # Documentación de frames

    Ventajas

    • Mismo código base para múltiples productos
    • Fácil mantenimiento de integraciones específicas
    • Switch dinámico sin recompilar
    • Aislamiento de lógica de cada CRM

    Componentes Principales

    1. Inicialización del Sistema

    Responsabilidad: Punto de entrada principal y validación de entorno

    Funcionalidades clave: - Validación de entorno y dependencias - Logging estructurado con niveles DEBUG/INFO/WARNING/ERROR - Inicialización del sistema

    2. Motor Principal

    Responsabilidad: Orquestación de todos los componentes

    Componentes gestionados: - Core: Configuración y estado global - API: Cliente Teamleader/OAuth - Recording: Grabación de audio (interna/OBS) - TaskManager: Sistema de gestión de tareas - CallProcessor: Detección de estados de llamada - GUI: System tray y menús

    Flujo de trabajo: 1. Detección de estado de llamada 2. Inicio automático de grabación 3. Búsqueda en CRM 4. Apertura de ficha de cliente 5. Procesamiento con IA al finalizar 6. Creación automática de nota en CRM

    3. Sistema de Tareas

    Responsabilidad: CORAZÓN del sistema - gestión de grabación, IA, backup y plantillas

    Funcionalidades principales: - Grabación en segundo plano sin bloquear la interfaz - Procesamiento con IA de transcripciones - Backup automático de grabaciones - Procesamiento de plantillas personalizadas

    Características: - Ejecución simultánea sin bloquear interfaz - Validación de audio pre-IA (evita créditos desperdiciados) - Recuperación post-apagón desde CSV - A/B testing de prompts IA

    GestorCSV

    Persistencia de estado en hojatiempo.csv: - Registro de todas las llamadas - Estado de procesamiento (audio, IA, CRM) - URLs de notas creadas - Recuperación automática tras corte de luz

    4. Configuración Unificada

    Responsabilidad: Configuración centralizada con recarga en caliente

    Funcionalidades: - Teamleader API (OAuth2, tokens) - Sistema de multi-idioma - Gestión de licencias - Recarga en caliente sin reiniciar

    Recarga dinámica: - Detecta cambios en config.ini - Recarga variables automáticamente - Reinicia traductor - Actualiza configuración de grabación

    5. Cuadro de Mando

    Responsabilidad: Gestión de interfaces de configuración

    Interfaces disponibles: - Configuración: Panel de configuración general - Hoja de tiempo: Registro de llamadas - Pre-notas: Gestión de notas predefinidas - Notas: Creación y gestión de notas

    Características: - Interfaces web de gestión - Supervisor para evitar múltiples instancias - Cierre por inactividad

    Sistema de Recuperación

    Persistencia en CSV

    hojatiempo.csv es el MECANISMO DE RECUPERACIÓN del sistema:

    Columna Descripción
    telefono Número telefónico
    fichero Ruta del audio grabado
    entidad Contacto/Empresa encontrada
    tiempo Duración de llamada
    estado Audio finalizado, IA disponible, etc.
    url URL de nota en CRM

    Recuperación Post-Apagón

    El sistema recupera automáticamente las llamadas no procesadas: 1. Lectura del CSV 2. Filtrado de registros sin IA 3. Validación de archivos existentes 4. Reprocesamiento con IA 5. Notificación al usuario

    Sistema de Validación

    Limpieza de Audio (libwertyaudiolimpieza.py)

    AudioCleaner.prepare_wav_for_ia(): - Tamaño mínimo: 4096 bytes - Duración mínima: 0.8 segundos - Formato válido: WAV/MP4 - Checksum SHA256: Integridad de archivo

    Reintentos automáticos: - 6 reintentos con 350ms delay - Para archivos recién creados - Evita procesamiento prematuro

    Integraciones

    Teamleader API

    OAuth2 Flow: - client_id, client_secret - tl_access_token, tl_refresh_token - Refresh automático de tokens

    Operaciones: - Búsqueda de contactos/empresas - Creación de notas/pre-notas - Lookup por número telefónico

    OBS Studio (WebSocket)

    Control remoto: - Control de grabación remoto - Grabación de audio del sistema

    Configuración: - Host OBS configurable - Puerto OBS configurable - Modo de audio seleccionable

    Circuit Breaker

    Aislamiento de Fallos

    Sistema de aislamiento: - Detecta fallos en servicios externos - Aísla servicios con problemas - Reintenta conexiones automáticamente

    Servicios monitoreados: - OBS Studio - Teamleader API - OpenRouter API

    Health Checks

    Monitorización

    Sistema de monitorización: - Comprobaciones periódicas de estado - Métricas de rendimiento - Endpoints para monitoring

    Componentes verificados: - OBS Studio conectado - API CRM respondiendo - Sistema de archivos accesible

    Logs y Debugging

    Logging Estructurado

    Niveles: - DEBUG: Detalles de ejecución - INFO: Eventos importantes - WARNING: Alertas no críticas - ERROR: Errores con traceback

    Archivo: log_centralita.log

    Limitación actual: Sin rotación de logs. Para producción de larga duración, recomendar RotatingFileHandler.

    Archivos de Configuración

    config.ini

    Archivo MONOLÍTICO que controla TODO:

    [API]
client_id=...
client_secret=...

[AUDIO]
inicio=d:\centralita_ia\rec

[MODULOS]
buscar=1
audio=1
ia=1

[IA]
api_key=...
intrucciones=...

[OBS]
obs_activo=True
obs_host=localhost

[BACKUP]
tiempo_backup=24
dirbackup=d:\backups

[WINDOWS]
idioma=es
tema=DarkBlue16

    Observaciones Importantes

    1. CSV como base de datos distribuida: hojatiempo.csv no es solo un log - es el MECANISMO DE RECUPERACIÓN. Si se corrompe o borra, se pierde la capacidad de recuperar llamadas tras apagones.

    2. Configuración en tiempo real: El sistema permite recargar configuración SIN REINICIAR, crucial para usuarios que ajustan prompts frecuentemente.

    3. Sistema de licencias: La licencia controla qué módulos están activos. Las funciones verifican la licencia antes de ejecutar.

    4. Menú dinámico: El menú se construye según licencia y configuración - módulos no autorizados no aparecen.

    5. Limpieza de audio obligatoria: El sistema valida TODOS los audios antes de enviarlos a IA, previniendo desperdicio de créditos API.
